## 0.0.15-pre

Per-module library support (phase 1 of the multi-module design,
`docs/research/ffigen-js-multi-module.md`):

- `NativeLibrary.init(moduleName, {makeDefault})` registers and returns the
  library for a module name; `NativeLibrary.byName(moduleName)` retrieves it.
  The first module initialized with `makeDefault: true` (the default) claims
  the ambient slot; later claims by a different module are ignored with a
  warning. `NativeLibrary.setDefault` exposes that policy directly.
- Every runtime helper now also exists in an instance-scoped form on
  `NativeLibrary` (`malloc`, `free`, `toNativeUtf8`, `utf8ToString`,
  `makeUint8List`, ..., `addressOf`, ...). The ambient top-level helpers are
  unchanged and delegate to the ambient library.
- Generated bindings keep their own per-file `GeneratedBindings.instance`
  (falling back to the ambient library until `initBindings` is called), and
  struct/global/function-pointer code dispatches through it instead of the
  ambient library. Bindings generated by earlier versions keep working
  unchanged.
- The generated `initBindings` takes `([String? moduleName,
  bool makeDefault = true])` and registers through `NativeLibrary.init`.
- The `ffi-native: asset-id:` config (same shape as `package:ffigen`) now
  bakes the module name into `initBindings` as its default argument - the
  ffigen_js analog of ffigen baking the asset id into `@DefaultAsset`.
- Ambient `malloc` now tracks its allocations so the ambient `free` actually
  releases them (previously `Pointer.free` only freed `addressOf` copies).
- Adds `tool/multi_module_smoke` (dart2wasm + node harness against two fake
  Emscripten modules) and a legacy-bindings compatibility test.
